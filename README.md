# Adaptive Hybrid IDS: CNN Feature Extraction + XGBoost Classification

> **Phase 1–3 (50% scope)** — Preprocessing, model training, and evaluation.  
> Phases 4–7 (hyperparameter tuning, ablation, explainability, dashboard) are **out of scope** for this release.

## Overview

This project implements an **Intrusion Detection System (IDS)** that combines a **1D Convolutional Neural Network (CNN)** for automatic feature extraction with **XGBoost** for classification of network traffic flows. The system is evaluated on the **CIC-IDS2017** dataset (MachineLearningCSV variant).

Three experiments are conducted:

| Experiment | Description |
|---|---|
| **Baseline A** | XGBoost trained directly on preprocessed/scaled flow features |
| **Baseline B** | CNN-only classifier with softmax output |
| **Proposed Hybrid** | Frozen CNN as feature extractor → XGBoost trained on learned embeddings |

The primary evaluation metric is **Macro-F1** (not accuracy alone), reflecting the class-imbalanced nature of network traffic data.

## Dataset

**CIC-IDS2017 — MachineLearningCSV variant**

- **Source**: Canadian Institute for Cybersecurity, University of New Brunswick  
- **Citation**: Sharafaldin, I., Lashkari, A. H., & Ghorbani, A. A. (2018). *Toward Generating a New Intrusion Detection Dataset and Intrusion Detection Using Machine Learning.* In Proceedings of the 4th International Conference on Information Systems Security and Privacy (ICISSP), pp. 108–116.  
- **Download**: [https://www.unb.ca/cic/datasets/ids-2017.html](https://www.unb.ca/cic/datasets/ids-2017.html) (MachineLearningCSV folder)
- **Contents**: Pre-labeled network flow features generated by CICFlowMeter across 5 days of simulated normal and attack traffic (DoS, DDoS, Brute Force, Web Attack, Infiltration, Botnet, PortScan).

## Design Decisions & Anti-Leakage Safeguards

| Decision | Rationale |
|---|---|
| **Drop rows with inf/NaN** instead of imputing | Inf values in `Flow Bytes/s` / `Flow Packets/s` are CICFlowMeter artifacts from zero-duration flows — not meaningful missing data. ~0.1% of rows affected. |
| **StandardScaler fit on training set only** | Prevents information leakage from val/test distributions into training |
| **Stratified splitting** | Maintains class proportions given extreme imbalance (BENIGN ~80%+) |
| **CNN frozen before embedding extraction** | Ensures two-stage architecture (not end-to-end), per project spec |
| **Feature order saved in config.yaml** | Guarantees consistent column ordering across train/val/test/inference |
| **Macro-F1 as primary metric** | Accuracy is misleading with class imbalance — macro-F1 weights each class equally |

## Metrics Reported (Per Experiment)

- Macro F1, Weighted F1
- Macro Precision, Macro Recall
- Per-class Precision / Recall / F1
- Confusion Matrix (saved as PNG)
- False-Positive Rate (per-class + macro)
- Training Time (wall-clock seconds)
- Inference Latency (ms/sample, median over test set)
- Model File Size (MB)

Results are saved to `results/` and aggregated in `results/comparison_table.csv`.

## Assumptions

1. **CPU-only training** — the pipeline works on GPU if available but doesn't require one.
2. **Python 3.12** with TensorFlow ≥ 2.16 (first version with official 3.12 support).
3. **Dataset encoding** — loaded as `utf-8-sig` to handle BOM characters in some CIC-IDS2017 CSVs.
4. **No fixed label list** — labels are discovered dynamically from the data; no hardcoded attack type list.
